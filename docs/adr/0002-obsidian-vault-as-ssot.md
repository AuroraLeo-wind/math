# ADR-0002：Obsidian vault 作为唯一权威来源，三路召回 + 常驻检索服务

- 状态：已接受（取代 ADR-0001 的「skill 包为产品本体」定位）
- 日期：2026-11-01

## 背景

ADR-0001 确定的形态是「Agent Skill 包为产品本体，知识库是可选的本地数据后端」。用了两轮之后暴露出三个问题：

1. **数据不可读、不可改**。2375 张卡是 JSONL 单行记录，要修一张卡的标题得手写 JSON；实测有 1343 张卡的标题是正文句子（如「可见二项分布就是由n 个相互独立的0‑1分布叠加而来.」），这批必须人工改，JSONL 不是能干这件事的载体。
2. **没有人的操作界面**。巡检「哪些骨架节点没有证据卡」只能用脚本打印，没有可浏览、可跳转、可写批注的界面。
3. **skill 是调用层，不是知识库**。skill 解决「怎么问、怎么引用」，但解决不了「知识放在哪、怎么改」。把知识库塞进 skill 目录会让两者都无法独立演进。

同时项目已有一个 Obsidian vault（`D:\文档\Obsidian Vault`，内容为 C++/后端笔记，27 个 md、零插件），说明使用者本身就在用 Obsidian。

## 决策

**知识库改为 Obsidian vault，它是唯一权威来源（SSOT）；检索引擎是独立常驻服务；skill 留作之后的调用层。**

九条配套决策：

| # | 决策 |
|---|---|
| 1 | RAG 主要用于**外部 AI 对话**调用；Obsidian 只承担编辑器与巡检面板 |
| 2 | vault 同时容纳**导出的证据卡**与**使用者手写笔记**；Markdown 为 SSOT，JSONL 降为派生物 |
| 3 | 上**本地向量**（不依赖 API） |
| 4 | 嵌入模型 `bge-m3`（1024 维 / 8192 token），**整卡一个向量不切块** |
| 5 | 三路召回：节点 BM25 + 卡 BM25 + 卡向量，用 **RRF** 融合 |
| 6 | 本地常驻 HTTP 服务（`127.0.0.1:8765`）+ 文件监听，CLI 退化为薄客户端 |
| 7 | 骨架节点在 vault 里是 **heading**，挂载用 `[[章#节点]]` |
| 8 | 手写笔记与证据卡检索等权，**输出分两区**，靠 `doc_type` 决定出处写法 |
| 9 | 评测集半自动（自动 50 条 + 手写 10 条），验收线见 PRD-0002 |

## 为什么不是别的

**为什么 vault 是 SSOT 而不是 JSONL**：要手改 1343 张卡标题，这是硬需求。Markdown 有搜索、反向链接、大纲、批量替换可用；JSONL 没有。改造后 JSONL 由 vault 反向导出，可随时重建。

**为什么整卡不切块**：卡里有最长 2000 字的 `raw`，「失效边界」「陷阱」经常在长文后半段。切块会切断它们，且会引入「段级引用」这层新概念，与现有引用纪律（卡 id + 页码）冲突。`bge-m3` 的 8192 上下文足够覆盖整卡。

**为什么三路而不是纯向量**：骨架路径是使用者自己的分类法。实测「看到加减相消就想泰勒展开」这条查询，节点路直接命中 `函数极限/解题思路结构化/泰勒展开/简单展开/加减关系`——这种「症状词 → 自己的归类」映射，向量只能靠语义猜。但只走节点路会漏掉「卡正文匹配但节点名不含该词」的情况，所以加卡路。三路融合是覆盖最全的选择。

**为什么不选纯 CLI**：`bge-m3` 加载要 5–10 秒，纯 CLI 每次查询都付这笔钱，高频使用无法接受。常驻服务同时解决了「改了 md 想立刻查」的近实时需求。

**为什么节点用 heading 而不是独立文件**：节点本身没有内容（只有名字），做成 heading 就同时获得 `#` 精确引用与反向链接，且文件数保持 43 个。独立文件会产生 1748 个文件，其中 269 个是「进阶练习/视频链接」这类噪声空壳。

## 后果

**好处**

- 知识库可读、可编辑、可巡检；修卡标题、补手写笔记都变成 Obsidian 内的日常操作。
- 检索与知识存储解耦，各自独立演进。
- skill 之后接入只是换一层壳：调 HTTP 或 CLI 都行。

**代价**

- **Markdown 成为 SSOT 后，导出脚本不能覆盖手改内容**。必须区分「导出区」与「手改区」，或改用「导出一次、之后只做反向导入」的单向流程。
- **同名章有两个版本**（`kk函数极限` 与 `函数极限(自测版本)`）会让 heading 重复。需在 MOC 层按版本拆文件，或先做数据去重（建议后者：4 本自测版是简化重排）。
- **bge-m3 依赖 torch**，磁盘约 3 GB（torch ~1 GB + 权重 ~2.2 GB），Python 3.13 已实测可装（torch-2.15.0）。`fastembed` 的 ONNX 路线装不了 bge-m3。
- **常驻进程需要管理**（端口占用、僵尸进程）。缓解：pid 文件 + CLI 自动拉起 + `--stop` 命令。
- 手写笔记的出处只能到文件级（`vault: 03-笔记/xxx.md`），不能到段落，除非笔记也加 heading。

## 与 ADR-0001 的关系

ADR-0001 的**骨架重建算法**（矢量连线定父子）与**挂载算法**（章名双向包含 + 节点名加权）继续有效，是数据层的地基。

ADR-0001 的**产品形态结论**（skill 包为产品本体、KB 为可选后端）被本 ADR 取代：知识库升级为 Obsidian vault 并成为 SSOT，skill 降级为未来的调用层。
