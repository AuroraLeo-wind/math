# ADR-0003：技术栈基线

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR-0002 确定了架构（Obsidian vault 为 SSOT、三路召回、常驻检索服务、`bge-m3` 整卡嵌入）。但技术栈基线一直没锁定：HTTP 框架、测试方式、配置机制、质量门禁全部空白。这不阻塞数据层（已建成），但阻塞下一个 issue 开工——写 `/search` 第一行代码之前，必须知道用什么框架、怎么测、配置从哪读。

本 ADR 按 grill 的技术栈 14 项逐一锁定。凡「无」的项也记录下来，因为它同样是决策，且能防止未来读者误以为遗漏。

## 决策表

| # | 项 | 决策 |
|---|---|---|
| 1 | 语言策略 | **Python 3.13 单语言**（本机 3.13.0）。数据抽取、索引、服务、CLI 全在同一运行时 |
| 2 | 后端框架 | **FastAPI + uvicorn**。OpenAPI 自动生成为接口契约的唯一权威来源 |
| 3 | 数据库 / ORM | **无数据库**。Markdown 为 SSOT；BM25 索引落 `.pkl`；向量索引落 `.npz`；无 ORM、无迁移 |
| 4 | 缓存 / 队列 / 调度 | **无**。近实时靠文件监听 + mtime 比对，不引入 Redis/Celery |
| 5 | Web 前端框架 | **无**（headless）。产品形态是 vault + HTTP 服务 + CLI |
| 6 | 移动应用 | **无** |
| 7 | 多包管理 | **单项目，非 monorepo**。`src/scripts/` 平铺，无包管理器抽象 |
| 8 | 认证 / 会话 | **无认证**。服务只绑 `127.0.0.1:8765`，安全边界是「本机用户」 |
| 9 | 契约 / 文档机制 | **FastAPI 自带 OpenAPI**（`/docs`、`/openapi.json`）。不手写接口文档，不引入外部契约工具 |
| 10 | 测试基线 | **pytest 分层**：`TestClient`（ASGI 直连，毫秒级）为主力；`@pytest.mark.smoke` 真起 uvicorn 的 3–5 个闭环用例；默认回路 `pytest -m "not smoke"` |
| 11 | 质量与 CI 门禁 | **不建 CI**。唯一门禁为 `python -m tools.check`（pytest 快速回路 + `check_kb.py`）。**刻意省略，非遗漏** |
| 12 | 环境 / 配置 / 密钥 | **`config.toml`（`tomllib` 标准库）+ 环境变量覆盖 + CLI 参数**。优先级：CLI > 环境变量（`MATHKB_*`）> `config.toml` > 代码默认值。无密钥需求（本地模型，无 API key） |
| 13 | 可观测性 | **文件日志 + stdout**。`logs/server.log` 按 10 MB 轮转保留 3 份；`GET /health` 暴露索引规模、模型名、uptime |
| 14 | 部署形态 | **本地单进程**。手动 `start|stop|status`，pid 文件在 `.run/`（gitignore）。不做容器、不自启、不反向代理 |

**UI 模式：headless** —— 无可视化页面，不创建 `docs/design/`，跳过全部 UI 门禁。

## 关键取舍理由

**为什么 FastAPI 而不是 Flask 或 `http.server`**：项目里有 6 个以上的接口参数需要校验（`/search` 的 6 个可选参数、`/reindex` 的 scope 枚举）。pydantic 一行一个字段就完成校验与类型转换，手写在 `http.server` 里是几十行。更关键的是它**顺手解决了第 9 项**——OpenAPI 自动生成，将来 skill 接入时不需要再手写一份接口文档。选 Flask 的唯一优势是熟悉度，代价是自建契约。

**为什么测试要分两层**：PRD 的 5 条测试决策里有 3 条是纯逻辑（RRF 单调性、vault 解析、引用校验），必须能用 `TestClient` 毫秒级跑，否则红绿循环转不起来。但 ADR-0002 决策 6（常驻服务 + 文件监听）**无法**用 `TestClient` 验证——它测的是「改了 md，查询结果变了」这条真实链路。冒烟层只保留 3–5 个用例，专盯这条链，多一个都不加，否则没人跑。

**为什么 `config.toml` 而不是 `.env`**：三路召回权重是嵌套结构（`weights = {node = 1.0, card = 1.0, vector = 1.0}`），TOML 原生支持，环境变量要自己发明编码。且 `tomllib` 是 Python 3.11+ 标准库，零依赖。四层优先级是为了 skill 分发：调用方一行 `MATHKB_VAULT=...` 就能指向自己的库。

**为什么无数据库**：数据形态是 Markdown（人读人改）、BM25 倒排（内存对象）、向量矩阵（稠密数组）。三者都不需要事务、并发写、关系查询。引入 SQLite 只会增加一层「索引与文件不一致」的风险——而 vault 作为 SSOT 的整个前提就是「文件说了算」。

## 刻意省略（非遗漏）

以下四项是**明确决定不做**，不是还没做。未来若有人（或未来的自己）觉得缺了，请先看这里的理由再推翻：

| 省略项 | 理由 | 什么情况下推翻 |
|---|---|---|
| **CI（GitHub Actions）** | CI 解决「别人合入会破坏」的问题；本项目单人维护，且改动主要发生在 Obsidian 里，CI 拦不住 | 开始向他人分发 skill 时 |
| **数据库 / ORM** | 见上，三种数据形态都不需要 | 需要多用户并发写或多机同步时 |
| **认证 / 会话** | 服务只绑 `127.0.0.1`，安全边界就是本机登录用户 | 要跨机器访问时（届时需 TLS + token，不是本 ADR 加个参数能解决的） |
| **开机自启 / 容器化** | 使用场景是「做题时才用」，非常驻。开机常驻会白占 2 GB 内存换一个用不到的端口 | 变成团队共享服务时 |

## 后果

**好处**

- 下一个 issue 可以直接开工：框架、测试方式、配置位置、门禁命令全部确定。
- 接口契约零维护成本（OpenAPI 自动）。
- 质量门禁落在正确的位置（数据体检 `check_kb.py`，而不是只测代码）。

**代价**

- **文件监听与自动拉起在自动化测试里是盲区**，只有 3–5 个冒烟用例覆盖。这两条路径是日常高频使用，出问题时会疼。
- **不建 CI 意味着没有人帮你发现「改 A 弄坏 B」**。缓解手段全靠 `python -m tools.check` 的自律。
- **`config.toml` 的真实文件不入库**（本机路径不外泄），换机器要照 `config.example.toml` 重填。
- FastAPI/uvicorn/pydantic 约 15 MB，相对 torch + bge-m3 的 3 GB 可忽略，但确实不再是「零依赖脚本」形态。

## 与其它 ADR 的关系

- ADR-0001：骨架重建与挂载算法 —— 继续有效，是本 ADR 第 1、3 项的数据来源。
- ADR-0002：vault 为 SSOT、三路召回、常驻服务 —— 本 ADR 是它的技术栈落地。
- ADR-0002 的决策 4（`bge-m3` 整卡嵌入）决定了本 ADR 第 12 项必须包含「模型名 / 本地路径 / device」三个可配项，以及第 13 项的健康检查要暴露模型状态。
