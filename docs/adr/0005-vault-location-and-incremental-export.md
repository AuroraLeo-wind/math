# ADR-0005：知识库并入现有 Obsidian 库的专属子目录，增量导出为默认

- 状态：已接受
- 日期：2026-11-06
- 关联：ADR-0002（vault 为 SSOT）、ADR-0003（技术栈基线）

## 背景

ADR-0002 定了「Obsidian vault 是唯一权威来源」，但没定库在哪、也没解决它自己列出的代价：「导出脚本不能覆盖手改内容」。现状是使用者已有一个 Obsidian 库（`D:\文档\Obsidian Vault`，内容为 C++/后端笔记，27 篇、零插件），而 2375 张卡里有 1343 张标题是正文句子，必须人工改写——这要求一个可编辑的界面，且要求改写不被下一次导出冲掉。

## 决策

1. **并入现有库的专属子目录**：`D:\文档\Obsidian Vault\考研数学\`。理由：Obsidian 与 MCP 已指向该库，零配置；同库可跨科目双链（数学节点 ↔ 编程笔记）；隔离靠目录前缀（`path:考研数学`）而不是拆库。库内其它笔记只读不碰，脚本的写入路径全部硬编码该前缀。
2. **Markdown 是 SSOT，JSONL/索引是派生物**：提供从 vault 反向解析的回灌脚本，任何检索改动前先把 md 改动回灌。
3. **增量导出为默认行为**：只把库里不存在的内容写进 vault，已存在的一律不覆盖。全量重建必须显式 `--force`，且先自动备份到 `vault/.backup/<时间戳>/` 并二次确认。字段级 `edited` 标记只作兜底，不作主策略。
4. **工作台是脚本生成的静态清单页，不是动态查询**：`00-工作台/` 下三页（待修标题 / 待审提议 / 空壳节点）。选静态而不选 Dataview/Bases 的理由是硬的：动态查询的结果只在渲染时存在、不落盘，而本知识库的消费者除了人还有 AI——RAG 读到的是空白代码块。
5. **视图只做章级派生**：Mermaid 在每章 MOC 顶部渲染骨架树（节点超过阈值时只画浅层），需要看全树时另开 markmap 页；不做画布双向编辑（见 ADR-0004 第 5 条）。

## 被否决的备选

- **新建独立库**：干净，但要切库、MCP 需重指、跨科目双链断掉；隔离需求用目录前缀就能满足。
- **把 `D:\math` 仓库本身当 vault**：git 天然管版本，但会让 Obsidian 索引几百 MB 的中间产物与代码目录，启动变慢、`git status` 噪音大。
- **导出区/手改区物理隔离 + override 层**：重建绝对安全，但 Obsidian 里看到的不是真实文件内容（改标题要开两个文件），破坏"直接整理"。
- **字段级合并为主**：只要有一次漏标 `edited`，改动就丢；"默认不动"更符合 SSOT 承诺。

## 后果

- vault 里会同时存在数学内容（两千多个 md 文件）与原有编程笔记，搜索与关系图需要用目录前缀过滤；`Omnisearch` 与 `Obsidian Git` 承担检索与版本回滚，成为仅有的两个插件依赖。
- 增量策略的代价是：抽取算法改进后，旧卡的错误标题不会被自动修好——但那本来就要人工改写，属于同一个动作。
- 备份目录必须在库内可见（便于人工回滚），且不进检索扫描范围。
