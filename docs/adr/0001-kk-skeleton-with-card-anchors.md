# ADR-0001：以 KK 导图节点树为骨架，证据卡挂载其上，检索走 BM25 + 树扩展

- 状态：已接受
- 日期：2026-11-01

## 背景

考研数学笔记资料共 122 个 PDF（KK 可视化导图 43 本、epsilon-delta 手写板书、27 大雪深埋做题本、张宇系列）。目标是用 AI 依据「自己的笔记方法论」解题。

有三条路可选：

1. **通用 RAG 平台**（RAGFlow / AnythingLLM）：PDF 切 chunk → 向量检索。
2. **纯卡片库**：把每份资料抽成结构化卡，平铺存 JSONL，BM25 检索。
3. **骨架 + 证据**：以 KK 导图的节点树为组织轴，其他资料的卡挂载到节点上。

旧工程实现过第 2 条：2375 张卡、BM25 索引，但导出产物 `10-method-index.md` 暴露了它的失败——「方法名」列里混进了正文句子（如「可见二项分布就是由n 个相互独立的0‑1分布叠加而来.」），「识别信号」列大量为空，「学生怎么说」列几乎全空。根因是**卡没有挂载位置，抽取时无从校验**。

KK 导图的结构恰好提供了这个校验位置：四栏 + 层级路径。

## 决策

采用第 3 条。

- **骨架**：`kb/nodes.jsonl`，43 本导图重建为 1748 个节点，每本一个书名根，四栏归属，`path` 为完整树路径。
- **证据**：`kb/cards_anchored.jsonl`，2375 张卡，`kk_anchor` 指向骨架节点。
- **检索**：`query.py` 走四步 —— 节点 BM25 召回 → 树扩展 ±1 层 → 取节点上的证据卡 → 按字符预算裁剪。
- **不引入向量库**：数学符号与公式让 embedding 退化，且 BM25 + 树结构可解释、可 diff、可离线重跑。

## 骨架重建的关键技术结论（三条被实测否掉的路）

1. **文字 block 的 x0 聚类**（旧 `build_kk_outline.py`）：导图标题文字在框内居中，框宽不等导致 x0 漂移。旧脚本注释自己写了「不做严格父子推断，避免伪造层级」。
2. **框的 x0 聚类**：mindmap 是「父框垂直居中于子框组、父在左子在右」布局，父宽度不同导致同层框左缘不对齐，实测聚出 21 个伪层（真实深度 4–6）。
3. **最终采用：矢量连线定父子**。KK 的连接线是正交折线（父框右缘 → 肘部 → 子框左缘），垂直脊柱两端 y 精确等于两个框的垂直中心，脊柱 x 落在父框右缘与子框左缘之间。据此可精确解出父子边，再对少数未连上的节点做几何最近邻兜底。

## 后果

**好处**

- 每个结论都能回指「KK 路径 + 资料页码」，skill 的引用规范（SKILL.md §6）才可执行。
- 卡的方法名有位置校验：抽取时若标题是正文句子，挂载会失败或被标低置信。
- 检索可解释：`--prompt` 输出里骨架路径与证据卡分离，模型不会把节点名当成结论。

**代价**

- 骨架只有节点名，没有内容（框内是公式截图）。节点无卡时必须在输出里明说「笔记里只有结构」，这是 SKILL.md §8 的硬约束。
- 22 本导图本身没有四栏标签（用「核心知识点」「基本方法」这类自然节点），其节点标为 `unsectioned`，栏过滤对这些书不可用。
- 挂载依赖词面重叠，当前覆盖 75%（1789/2375），剩余 586 张卡章节名与骨架对不上，进 `build/anchor_review.tsv` 人工抽查。

## 备选方案（未采用的理由）

- **RAGFlow / AnythingLLM**：chunk 化会把「识别信号 → 适用条件 → 失效边界 → 标准动作」切成互不相邻的碎片，检索回来的公式残片无法支撑方法论输出。
- **纯卡片平铺**：就是旧工程的状态，已证明会退化成「方法名是正文句子」。
- **标题/页码手工映射**：2375 张卡 × 手工，成本不可接受，且无法随新资料增量更新。
